# 聊天桥与旧 Rin 的能力差距

核对日期：2026-09-05。范围为聊天接入、收发体验、身份、消息语义与恢复，不包括旧 Rin 的全部业务技能。依据是当前源码、部署配置、实际平台回执、旧实现及规范消息库；单元测试不代表平台验收。

本轮确认：1项正在使用的图片链路缺陷（已修复部署，待新的有效回复窗口完成发送验收），至少5类明确功能差距，另有5类验收空白。不能再描述为已与旧版整体对齐。

## 本次 QQ 图片故障

QQ 入站图片已实际下载并被模型查看，图片生成工具也已成功完成。故障在 App 输出观察：原实现只读取 `agentMessage` 和 `reasoning`，遗漏独立的 `imageGeneration` 结果；普通附件允许目录也未覆盖任务自己的生成图片。

修复已部署到 persona-10：观察已完成图片结果的 `savedPath`，不读取或外发工具原始输出、图片生成提示词及 base64；按任务自己的生成目录校验真实路径，通过持久出站队列投递，保留 QQ 原消息关联，重启去重。显式 Markdown 图片链接也可引用同一任务的生成目录。58项相关测试通过（后补路径修正后45项受影响测试再次通过）。

真实补发尝试中，图片上传接口返回成功，但 QQ 消息发送返回“msgid已经过期,不能回复”。因此“图片上传”已验证，“修复后图片最终抵达群聊”尚未验证。失败项保留，未自动重放；需要新消息提供有效被动回复窗口。旧版 OneBot 的发送方式不能作为 QQ 官方 API 的时限保证。

源码证据：`src/chat/codex.mjs`、`src/chat/bridge.mjs`、`src/chat/files.mjs`、`src/chat/adapters/qqbot.mjs`；回归：`tests/chat-codex.test.mjs`、`tests/chat-bridge.test.mjs`。

## 五类明确差距

| 类别 | 旧版能力 | 新版现状与影响 |
|---|---|---|
| 身份与信任 | 人物身份、可信关系、多个平台账号映射 | 直接聊天桥主要是各平台 `allowUsers`；Nerve 有主人识别，但不是完整人物身份层。历史中认识的人不等于已补齐新平台权限，QQ任务入站正文也没有完整身份上下文。 |
| 引用上下文 | 规范记录可保存引用正文、作者与消息元素 | 新直接桥多数仅保留 `replyTo` 标识，模型未必知道被引用内容。出站带引用不代表入站引用语义完整。 |
| OneBot 富媒体与合并转发 | 旧实现解析语音、音频、视频、表情、合并转发，并可展开转发内容 | 新 OneBot 入站主要处理 image/file；这些其他元素及 forward 展开缺失。虽然当前没启用，仍是必做适配器的真实差距。 |
| Telegram 消息更新 | 旧版处理 edited_message、channel_post 等事件 | 新版轮询只接收 message，消息编辑、频道帖等事件未接入。 |
| 执行状态展示 | 旧运行时提供 todo、上下文压缩等状态 | 新桥主要观察公开文字、摘要及本次新增图片结果；样式中有 todo 区域不代表已有真实 todo/压缩事件。 |

证据入口：`src/chat/policy.mjs`、`src/chat/adapters/{discord,telegram,qqbot,onebot}.mjs`、`src/chat/codex.mjs`。旧身份库与旧规范数据库仅在私人环境只读核对，不进入公开仓库。旧 OneBot 实现位于旧扩展仓库 `extensions/onebot-platform.ts`，重点为媒体归一化和 `get_forward_msg` 处理。

## 五类验收空白

这些表示没有足够证据，不能直接说功能缺失，也不能说已完成。

| 项目 | 当前证据 | 仍需验收 |
|---|---|---|
| QQ 官方媒体全链路 | 真人群文字往返、图片入站与模型看图已发生；发图上传成功，补发因超时被拒 | 修复后新窗口内图片抵达；语音、视频、文件实际发送；多段回复与额度/时限处理 |
| Telegram 入站 | 登录、轮询及部分真实出站格式已有证据 | 真人发文本、图片、文件到 App 后实际回复 |
| OneBot 实际接入 | 替身测试与协议实现 | 用户所用 OneBot v11 服务的真实收发、重连、媒体、引用；不预设 NapCat |
| 飞书实际接入 | 替身测试与适配器实现 | 账号配置与真实收发；当前未启用，不算已部署可用 |
| 故障恢复与自主对话 | 持久队列、不确定不重放、未加载 App 任务唤醒有部分实测 | 完整 App 重启、断网、漏收、取消、跨平台多段发送失败，以及 Discord 注意力无人纠正情况下的自主图片回复 |

恢复策略不要求机械复制旧数据库的 lease 等字段；要按用户可见行为验收。新桥依赖 App 的特定私有历史投影版本，版本变化有停观察风险；这也是维护成本，不是端到端验证可以替代的问题。

## 平台限制与范围决定

QQ 官方没有普通消息编辑/删除能力，typing 仅 C2C；OneBot v11 没有标准编辑/typing；这些不能通过复制旧桥实现抹平。QQ 官方与 OneBot 必须分别评估和验收。

旧记录还有 Matrix、GitHub 聊天来源。它们不在当前五适配器实现中，不能冒称已迁入；是否恢复应另行确定，未计入上面五类已确认差距。

## 后续优先级

1. 完成当前 QQ 生成图片的真实投递验收，补齐超时失败的用户可见结果，避免只有“做好了”而没有产物。
2. 补最小人物身份映射及入站引用内容，让模型知道谁在说话、引用了什么。
3. 补 OneBot 媒体与合并转发语义，再做真实平台验收。
4. 明确 Telegram 更新事件和执行状态展示的保留范围，完成故障恢复演练。

本报告是本轮有边界的审计，不是对旧 Rin 全部功能的穷尽证明。
